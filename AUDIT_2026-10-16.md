## B. Still open — Critical

### B1. Untracked files required by tracked code → deploy crash
- **Evidence:** `backend/src/utils/kycValidation.js`, `frontend/src/lib/kycValidation.js`, `frontend/src/lib/roles.js` are untracked. Tracked code imports them (`backend/src/routes/user.routes.js:7-13`, `frontend/src/App.jsx`, `frontend/src/components/MultiDocumentKycModal.jsx`).
- **Impact:** A commit/deploy that includes the modified tracked files but not these untracked ones fails at backend boot (`MODULE_NOT_FOUND`) and Vercel build time.
- **Fix (you):** `git add` these three files together with the two new Prisma migrations (`20260926...`, `20260928...`) and `migration_lock.toml`. They must be in the same commit.

### B2. Real secrets committed in git history
- **Evidence:** `backend/.env.example` at HEAD committed 128-hex `JWT_ACCESS_SECRET`, `JWT_REFRESH_SECRET`, and a 64-hex `ENCRYPTION_KEY` (introduced in `69045ca`). The working tree replaces them with `CHANGE_ME_` placeholders, but the values remain in the public GitHub history.
- **Impact:** If those values ever matched any environment, anyone could forge JWTs and decrypt stored UPI IDs.
- **Fix (you + code):** rotate both JWT secrets and `ENCRYPTION_KEY` in every environment; re-encrypt UPI values if the leaked key was used; purge history with `git filter-repo`/BFG; enable GitHub secret scanning.

### B3. Payment money movement is incomplete (no payout, no refund)
- **Evidence:** Only Razorpay order creation + payment fetch exist (`backend/src/services/payment.service.js`). No transfers/payouts/refunds anywhere; `TransactionType.REFUND` and `TransactionStatus.REVERSED` unused. Provider money is captured into the Razorpay account; borrower "disbursal" and provider payout exist only as DB rows.
- **Impact:** With real money, funds cannot legally/correctly reach borrowers or providers; captured-but-unapplied payments have no refund path.
- **Fix:** implement Razorpay transfers/payouts + refunds with idempotency and reconciliation, or explicitly gate `PAYMENT_PROVIDER=RAZORPAY` behind a manual-settlement flag and document the manual process.

### B4. Captured payments can be stranded (no refund, webhook 500 loop)
- **Evidence:** A funding reservation released by the sweep/null-`rzpOrderId` flow, or a superseded order, still receives a real `payment.captured` webhook. `markFundingCaptured` throws "Loan is not in FUNDED state" → route returns 500 → Razorpay retries forever; money stays captured.
- **Impact:** Customer money captured with no loan, no transaction row, no refund; webhook retry storm.
- **Fix:** record every captured payment idempotently (even orphan ones), auto-refund orphan captures, cancel superseded Razorpay orders, always return 2xx for recognized events.

## C. Still open — High

### C1. KYC queue exposure (partially fixed: FINANCE_ADMIN now gets no plaintext IDs, `passwordHash` removed from queue). Remaining: the user drawer in `AdminPanel.jsx` still displays full Aadhaar/PAN. Mask by default + audit logged "Reveal".

### C2. KYC approval without documents / no notifications
- **Evidence:** `backend/src/routes/admin.routes.js` patch `/kyc/:userId` has no check that a `kycDocument` exists or is complete, and never calls `createNotification`; `NotificationType.KYC_APPROVED/KYC_REJECTED/ACCOUNT_SUSPENDED` are unused.
- **Impact:** An account with no identity documents can be approved; users never learn their KYC/suspension outcome.
- **Fix:** require complete documents before APPROVED; only allow PENDING→APPROVED/REJECTED; create notifications in the same transaction.

### C3. KYC upload robustness
- **Evidence:** `backend/src/routes/user.routes.js` only byte-sniffs Aadhaar/PAN images; `frontFile`, `selfieFile`, `backFile`, `/kyc/liveness`, `/kyc/id-card` rely on multer's client `mimetype`; the base64 regex accepts `image/svg` and arbitrary bytes; 7×5 MB memory uploads; no cleanup of replaced objects.
- **Impact:** arbitrary bytes stored as KYC docs; stored-XSS risk via content-type confusion in admin viewer; Render OOM risk; unbounded R2 growth.
- **Fix:** run `validateDocumentImage` on every image path, restrict base64 types to jpeg/png/webp + size cap, delete replaced objects, per-user cooldown.

### C4. Deployment env mismatch for email + storage
- **Evidence:** `render.yaml` sets Gmail SMTP but production intent is Mailjet; `EMAIL_PROVIDER` not pointed at Mailjet; docs describe Gmail only. `R2_ACCOUNT_ID` was missing from `.env.example` and `render.yaml` (both fixed), but your actual Render service must now be updated.
- **Impact:** OTP delivery fails or falls back slowly; KYC uploads 500 without R2.
- **Fix (you):** set `EMAIL_PROVIDER=MAILJET_API` + `MAILJET_API_KEY/SECRET` + `SMTP_FROM` (sender) or fix the Gmail app password; set all `R2_*` keys.

### C5. Rate limiting is per-process memory and forces Redis
- **Evidence:** `backend/src/middleware/rateLimiter.js` uses default MemoryStore; Redis is only pinged at startup; production hard-requires `REDIS_URL`; `RateLimitLog` never written; 10 auth requests/15 min per IP will lock out campus NAT users.
- **Impact:** resets on restart, not shared across instances, shared-IP lockouts.
- **Fix:** configure `rate-limit-redis` + user keys, tune auth limits, or drop the Redis requirement.

### C6. Sweep/credit-score races and duplicated penalties
- **Evidence:** `backend/src/services/loan.service.js` `refreshLoanDelinquency` reads then updates; `updateScore` is read-modify-write; the sweep runs from the hourly job, admin POST and the GET queue; concurrent runs can double-apply −80.
- **Impact:** defaulters lose 160+ points; concurrent repayments lose score updates; admin queue polls run a full sweep.
- **Fix:** atomic claim on default transition, transactional/incremental score updates, never sweep from GET.

### C7. OTP delivery is synchronous, failure-tolerant and misleading
- **Evidence:** register/login await email; `sendOtpChannels` hardcodes `strict:false`; Gmail transport only 465 on send path; mail failure still returns "Check your email".
- **Impact:** 20 s blocking requests; users stranded unverified with no ops signal.
- **Fix:** async delivery, honor `SMTP_STRICT`, port 465→587 fallback, surface `sentAny=false`.

### C8. `resend-otp` unauthenticated + can trigger admin 2FA
- **Evidence:** `backend/src/routes/auth.routes.js:70-79` has no validation/auth; `RESENDABLE_OTP_PURPOSES` includes `ADMIN_2FA`; 3/min/IP.
- **Impact:** email bombing, invalidating codes, distributed-IP bypass.
- **Fix:** validate + require flow token; exclude ADMIN_2FA from public resend.

### C9. Production boot fail-open for Razorpay placeholders
- **Evidence:** `backend/src/index.js:15-26` downgrades Razorpay placeholder validation errors to warnings, even in production.
- **Impact:** deploy "passes" then every payment fails at runtime.
- **Fix:** only tolerate placeholders outside production.

### C10. `prepareDb` falls back to `db push` in production
- **Evidence:** `backend/src/scripts/prepareDb.js` on migrate failure runs `migrate resolve --applied 20260727000000_init`, retries, then `db push`; render start runs it every boot.
- **Impact:** schema drift and possible destructive reconciliation; seed re-runs on every cold start.
- **Fix:** fail hard on migrate errors in production; gate `db push` behind an explicit env; run migrations as a one-off.

### C11. Missing DB indexes + duplicate indexes
- **Evidence:** `transactions.rzpOrderId`, `loans.rzpOrderId`, `loans.rzpRepayOrderId` unindexed while filtered on hot paths; duplicate plain indexes on `RefreshToken.tokenHash` and `Transaction.idempotencyKey`.
- **Impact:** webhook/sweep latency grows with history.
- **Fix:** committed index migration; drop duplicates.

### C12. Missing database constraint for one active loan per borrower (race allows two)
- **Evidence:** `createLoan` check-then-create without serializable transaction or partial unique index.
- **Impact:** concurrent requests create two active loans; exposure above borrow limit.
- **Fix:** partial unique index on `(borrowerId)` for active statuses or serializable transaction.

### C13. `publicId` sequence breaks past 99,999
- **Evidence:** next id derived by lexicographic `orderBy publicId desc`; `UniFi#100000` sorts before `UniFi#99999`.
- **Impact:** collision + retry exhaustion → loan creation fails.
- **Fix:** Postgres sequence or fixed-width padding with longer cap.

### C14. No cleanup jobs (OTPs, refresh tokens, device sessions, notifications)
- **Evidence:** rows only filtered by `expiresAt` at read time; nothing deletes.
- **Impact:** unbounded table growth on free Postgres tier.
- **Fix:** periodic prune job / TTL strategy.
